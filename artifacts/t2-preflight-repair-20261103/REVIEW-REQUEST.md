## Revised design

All catalog object sections enumerate non-system schemas, using the literal prefix exclusion `^pg_` and information_schema exclusion, never search_path visibility or public-only filtering. Inaccessible non-system schemas are inventoried too; unsupported/unsafe metadata blocks. Qualified schema/table identities bind relations, policies, triggers, raw schema/relation ACLs, columns and routines. Inventory consistency rejects mismatched or missing schemas/relations and duplicate identities; a custom AuditLog cannot inherit the public table's permission exception, nor can a sibling policy/trigger satisfy a public-table guard. Built-in system catalogs/functions remain a provider/PostgreSQL trust boundary rather than arbitrary application objects.

Effective table/sequence, schema CREATE, database CREATE/TEMP, replication-parameter and routine EXECUTE privileges are evaluated across every direct/indirect MEMBER role. This conservatively includes NOINHERIT and SET ROLE paths even when a particular membership edge would not confer immediate authority. The A2 runtime topology additionally permits only preview_app itself, no group memberships. Owner reachability covers schemas, relations, types and routines; TRIGGER/TRUNCATE/REFERENCES/MAINTAIN and sequence/view/foreign-table access are outside the runtime allowlist.

Each physical column has schema/table/name, effective SELECT/INSERT/UPDATE/REFERENCES privilege union, effective WITH GRANT OPTION union, and raw column ACL entries including is_grantable. PostgreSQL has_column_privilege includes table-level authority too. Each member principal is checked explicitly, not by comparing raw grantee names to preview_app. Any effective column grant option blocks; raw inherited grant options also block. Defaults may not automatically grant anything to runtime/member roles. Unknown/missing effective arrays or ACL shape cannot pass.

Runtime data permissions now match the accepted A2 design's closed fixture SELECT list and AuditLog INSERT only. PolicyConfig/Timetable writes are denied intrinsically even with a re-fingerprinted synthetic policy. INSERT action/subject correctness, RLS predicate semantics and the complete new guard set are not proven by this static metadata evaluator and remain A2 gates. Ordinary callable SECURITY DEFINER routines, callable aggregates, routine ownership/delegation paths and external PUBLIC/provider execution grants block. Non-callable, owner-isolated routines in inventoried custom schemas require exact reviewed fingerprints.

Existing FORCE/ENABLE RLS, required twelve immutability guards, definition hashes, schema ownership, migration/remote checks and safe fixed output remain. Runtime groups cannot waive ACL findings. Read-only RepeatableRead collection now fixes search_path locally to pg_catalog before catalog queries. The legacy psql inventory wrapper does likewise. Neither SELECT collector executes a discovered routine or returns raw function bodies, policies, credentials or row data. Function/policy definitions remain server-side hashes; aggregate definitions are hashed from pg_aggregate metadata and callable application aggregates are refused.

Policy format advances to `preview-db-policy/2`. Version 1 is rejected, and the operator CLI refuses it before creating a Prisma client. The template remains UNAPPROVED, without accepted fingerprints. No real metadata was adopted as a policy. No schema-push-reviewed exception is granted by this patch. Collector SQL was inspected and exercised through mocked query dispatch, not executed by PostgreSQL in this task; no real-role, parser/engine, provider, performance or hosted acceptance is asserted.

Authoritative privilege semantics: [PostgreSQL 17 access inquiry functions](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-INFO-ACCESS-TABLE) and [membership/SET ROLE](https://www.postgresql.org/docs/17/role-membership.html). Their MEMBER/USAGE/SET distinctions and column grant-option checks inform the conservative union above.
