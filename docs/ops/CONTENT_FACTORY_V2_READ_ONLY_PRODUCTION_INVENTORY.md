1. Have the authorized operator supply credentials directly into an isolated process environment or established approved secret mechanism. Never put the URL/password in shell history, command arguments, screenshots, logs or the manifest. Record sanitized target identity and effective privilege/RLS verification in the access ticket. Confirm the role can see the intended full dataset and has no data-modification privileges. An empty result under default-deny RLS is not a complete inventory.
2. Prepare an access-restricted output directory outside the Git checkout and all public/sync/web directories. Create a unique UTC run directory; never overwrite an older export. Use an already installed approved PostgreSQL client to avoid pulling or provisioning resources. Generate 32 random bytes locally as hexadecimal in process variable `FACTORY_INVENTORY_REFERENCE_SALT`; retain the salt only in the restricted operator vault if later reference comparison is required. Never add it to the export or manifest.
3. Inspect the exact `scripts/content-factory-v2/production-inventory.sql` checksum and commit. Run only this reviewed file with `psql -X -q -A -t -v ON_ERROR_STOP=1 -f <reviewed-file>`, using PG environment authentication and the approved TLS/target settings. Capture stdout to `lessons.jsonl.partial` and stderr to a separate restricted file. Do not use the existing write-capable wrapper unmodified. The operator's approved launcher must preserve exit codes and UTF-8 without BOM. `-X` disables psql startup files; no application framework, Prisma client, arbitrary user SQL or shell SQL concatenation is involved.
4. The file starts one `REPEATABLE READ READ ONLY` transaction, uses only SELECTs and session-local timeouts and ends with ROLLBACK. It creates no table or server file and takes no explicit locking reads. Connection/statement failure, timeout, missing salt, incomplete output or any read-only assertion failure invalidates the run. Preserve the partial file for restricted diagnosis; do not promote it to inventory. Close the connection rather than retrying inside a possibly aborted transaction. A retry is a new capture directory and snapshot.
5. The capture records session timestamp, server version, snapshot identity, isolation, read-only status and salt-validity, then content-type counts and every `upper(contentType) = 'LESSON'` row across grades, subjects and publication states. Review all distinct content types before accepting completeness; if live lesson encodings differ, amend and review the SELECT predicate and rerun. The query never limits capture to Grade 7 or the two lead IDs.
6. Each row includes exact database and logical IDs, grade, subject, unit/order, version/lessonVersion, complete current payload, objectives, MOE/WAEC mappings, delivery profile and publication fields. It left-joins provenance so missing lineage is visible, includes every immutable revision's full snapshot/hash/sequence/source/prompt metadata, current revision reference and bounded governance metadata. It does not equate current mutable payload with the latest reviewed revision. Preserve both and investigate discrepancies.
7. Assignment/homework counts include direct database/logical-ID references and ScheduledWork joins, without double counting a row that matches both. `GradedSubmission` counts use its documented database-ID lessonId; teacher lesson and timetable assignment counts use their logical-ID relations. Submission counts remain separate by store. Summary assignment totals count relation rows across stores and do not claim a unique count of pedagogical tasks. StudentProgress and StudentSession are counted through ScheduledWork. LearningEvent references match exact contentId/lessonId against both legacy identity namespaces. Do not attribute records linked only by unitId, title, time or inferred pupil identity to a lesson. Generic `Submission` through unit-level `Assessment` has no authoritative direct lesson link and is not assigned to individual lessons; report this limitation. The query cannot prove that unstructured historical metadata carries no additional references.
8. A terminal `complete` row repeats the lesson count and read-only status within the same snapshot. The operator verifies successful psql exit and ROLLBACK completion before accepting the file. Database session/statement logs may record reads; this procedure performs no application or educational data writes.
