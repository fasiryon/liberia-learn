# Current user-facing surface inventory

Audit date: 8 October 2026. Exact base: `a5d0afd09bf8dd3a3919449022924afb16e69515`. This is a static repository audit, not an authenticated browser/session or full accessibility audit. All 339 `app/**/page.tsx` files are enumerated below, including redirects, gated/internal views and placeholders; existence does not prove exposure, correct RBAC, production use or working data. API handlers and backup files are not page surfaces. Static and parameterized lab URLs intentionally coexist.

## Dispositions and evidence limits

REUSE retains the foundation; REFINE improves presentation; REDESIGN changes workflow/hierarchy; CONSOLIDATE groups entry points while retaining capabilities/contracts; REPLACE retires a presentation after parity; REMOVE removes duplicate entry affordance only after preserved contextual access; DEFER retains a specialty/ownership-sensitive surface pending separately scoped review. No runtime removal is authorized by this inventory.

Each route row inherits all fields from its named profile: current purpose, actual user job, hierarchy/density issues, mobile/accessibility/offline concerns, duplication, Figma relationship and proposed V2 destination. Profiles express design assessment/risk, not confirmed failures for every page. Route-specific source facts and navigation entries are separate columns. This normalized structure avoids repeating identical role risks across hundreds of rows. Component links are immediate local TSX imports (up to five), with nav/footer/common containers documented separately; inline pages use their page component. An immediate import list is not proof of no transitive components.

Entry evidence: named navigation definitions when the exact URL is present; otherwise one literal inbound route string in a UI source; dynamic detail pages use parameterized parent-flow entry requiring browser verification. “No literal inbound found” is not proof of unreachable/dead code. Source facts report responsive utilities, fixed positioning, tables and local fetch calls in the page file only; component/layout behavior may differ. These identify review needs, not measured UX performance.
