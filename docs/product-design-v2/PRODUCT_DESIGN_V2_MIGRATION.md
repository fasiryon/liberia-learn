Name the relevant [matrix capability IDs](COMPETITIVE_UX_BENCHMARK.md#competitive-capability-matrix), public benchmark pattern/source and the [framework](PRODUCT_DESIGN_V2.md#competitive-strategy-adopt--improve--reimagine--differentiate). A composite PR uses separate labels for separate capabilities; the matrix remains the decision authority. Its implementation-dependency column is authoritative for capability-to-slice membership; the synchronized ID lists below include all capabilities assigned to each slice. Cross-cutting S20 accessibility applies to every slice. T13 is a deferred dependency/readiness check, not a PR 8 implementation commitment.

Required record: capability/user job → competitor pattern and evidence limits → disposition → useful behavior preserved → friction removed or new real capability → authorized dependency/current limitation → LL before/after task result → matched competitor result if claiming superiority → [scorecard A–G answers](PRODUCT_DESIGN_V2_SCORECARD.md#competitive-strategy-review-gate). Include current exact build/head and evidence links. Unmeasured superiority remains a hypothesis, even when absolute release gates pass. Visual screenshots alone cannot establish improved task performance. PR 3 releases the lesson presentation **only after** Curriculum V2's owner supplies a reviewed native LessonExperience/scene seam. PR 4 Labs, PR 5 Progress, PR 6 Help follow. PRs 4–6 can prepare independently while PR 3 waits, but cannot claim scene integration complete before the seam is released.

Each PR is reviewable on its own, with a feature rollout boundary appropriate to the repository. Existing routes remain working until the new contextual entry points pass. No broad style replacement, bulk redirect deletion or shared educational DTO change is part of these PRs. Record missing backend display capabilities and hand them to the owning track instead of introducing a shadow projection. Product review needs real data, empty, stale, denied, error and offline states, not only ideal fixtures.
