# Competitive UX benchmark: Canvas and Blackboard

Research date: 8 October 2026. Scope: current publicly accessible vendor guidance for Canvas web/Student/Teacher mobile/Elementary and Blackboard Ultra/LMS App. No authenticated competitor tenant, timed user study or independent accessibility conformance audit was performed. Documented paths are examples, not universal click counts. Institution configuration, license, instructor organization, content quality and app version affect behavior. Observed/public evidence (E) is separated below from inferred friction/opportunity (I) and LiberiaLearn's proposed targets (T).

## Competitive capability matrix

Use the [authoritative framework](PRODUCT_DESIGN_V2.md#competitive-strategy-adopt--improve--reimagine--differentiate). **E** is public evidence, **I** is our product judgment/inference, **T** is a future acceptance target. The first column cites source IDs from the registers; all remaining columns are I/T, not observed competitor deficiencies or implemented LiberiaLearn behavior. “Better/different” is the hypothesis to prove. No numerical competitor baseline has been measured. If a pattern is not covered by public evidence, the row says so rather than inventing a feature comparison.

Stable capability IDs are used by the [migration disposition table](PRODUCT_DESIGN_V2_MIGRATION.md#competitive-disposition-required-for-every-implementation-pr), [surface crosswalk](CURRENT_SURFACE_INVENTORY.md#competitive-strategy-crosswalk) and [review gate](PRODUCT_DESIGN_V2_SCORECARD.md#competitive-strategy-review-gate). PR numbers below are future implementation slices, not existing GitHub PR numbers. G01–G16 refer to the scorecard; capability-specific thresholds below are additional blockers for the affected slice. Task success means correct authorized result, not merely opening a screen. Unless a row specifies otherwise, timed targets start from a loaded entry, use the scorecard cohorts/networks and require at least 90% unassisted success. Online saves/publishing remain subject to existing policy.

## Competitive conclusions and limits

Task shortcuts, module Continue, mobile grading, offline reading, child-oriented layouts and AI already exist in the benchmark products. LiberiaLearn cannot claim an advantage simply by adding those features. Its proposed differentiation is combining authoritative next action, a learner-understandable reason, exact scene/objective help, evidence-aware progress, age-sensitive control affordances and resilient offline operations into the same task flow.

The friction column is product inference from public organization patterns. The acceptance column is LiberiaLearn's chosen performance budget, not competitor measured performance. No claim is made that either product universally has deep navigation, poor accessibility, no adaptive features or no AI. Current evidence does not prove superior learning outcomes. Learning efficacy needs a separately governed evaluation with matched curriculum/assessment, not click or completion gains alone.

The [scorecard](PRODUCT_DESIGN_V2_SCORECARD.md) defines cohort/device/network methodology, absolute blockers and the additional matched comparison required before a quantified superiority claim. Recheck vendor guidance and licensed features at each implementation release; current product capabilities can change.
