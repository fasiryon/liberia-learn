# Product Design V2 release scorecard

Status: required future release gates, all **NOT MEASURED** at foundation signoff. No Product Design V2 implementation is certified by this documentation PR. Base audited: `a5d0afd09bf8dd3a3919449022924afb16e69515`, 8 October 2026.

## Measurement protocol

Count primary actions as intentional button/link activations; auto redirects do not add a click but do count elapsed time and navigation transitions. Resume ends only when the correct authorized task is interactive, not at a discovery page with another Start button. Count destination depth below the role home; a dialog or selector needed to find the task adds a level. Authentication and required initial consent are measured separately, not used to inflate competitor comparisons. Never bypass them for speed.

Measure task time from the loaded home for comprehension/navigation studies and from navigation start for technical readiness; report both. Use identical assignment, scene objective and intervention tasks on representative authorized fixtures. Browser evidence uses 320, 360, 390, 768 and 1440 CSS px, touch and keyboard, 200% text/zoom and 400% reflow, reduced motion and forced colors. Test at least one low-memory Android phone and one tablet; simulated widths alone cannot certify performance.

Network profiles: normal 10Mbps/50ms RTT; weak 400kbps down/100kbps up/400ms RTT; offline after verified download; cold offline without download; repeated reconnect/disconnect. Record device/browser/build, fixture release/version, cache state, network throttle and timestamps. Cache-only readiness targets require a successfully provisioned authorized resource. Uncached offline tasks must produce an honest unavailable state, not meet an impossible launch target.

Usability release sample: at least 10 learners in each Grades 1–3 and Grades 4–7 cohort, 10 older learners where released, 10 teachers, and 5 guardians for guardian scope, with documented consent/approved study procedures. Include users needing assistive technology and limited digital familiarity. Compute per-cohort success and p90 time, not a pooled average that hides younger learners. Pilot results are directional; report sample size, failures and limitations. Automated fixture coverage validates all authority/error/offline paths independently of study sampling. Do not create new child-data telemetry for this mission; use approved studies and existing permitted events in later PRs.

Competitor numerical task-time/click baselines are **unmeasured**. [Benchmark](COMPETITIVE_UX_BENCHMARK.md) documents public patterns, not timed live trials. Before claiming competitive superiority, run comparable tasks on lawfully available current Canvas (including Elementary/new dashboard where enabled) and Blackboard Ultra/mobile configurations, recording version, institution settings and available AI/offline features. Target a ≥25% median task-time improvement on resume/assignment/intervention tasks against each measured baseline, without reducing accuracy or accessibility. If no comparable access is available, release can pass LiberiaLearn's absolute gates but marketing/completion reports cannot claim proven competitor outperformance.

## Blocking scorecard

Every row is release blocking for the surfaces in its scope. A mean score cannot compensate for a failed row. P1 safety/authority/accessibility/data-loss failures block regardless of cohort percentage. For each implementation PR record baseline, observed result, evidence link, build/head SHA, reviewer, PASS/FAIL/NOT MEASURED and remediation owner. NOT MEASURED blocks calling the affected scope complete. No waiver is implied here.

Card density counts visibly separate panels, not invisible DOM wrappers. Lists/sections should use whitespace and dividers; do not remove needed information simply to hit a count. At smaller first view sizes show essential next action before supporting panels. Display at most three high-priority teacher issues initially (deduplicated learner count plus See all) and five plan rows in middle/adult mode, three in young mode. A required safety/consent flow may supersede this view; optional install/push/tour prompts may not.

## Offline capability and recovery gate

These are presentation contracts over existing policies, not permission to add offline writers. A type name in the queue is not proof that every route supports it. Verify each route's wiring before showing Available offline.

| Capability | Available / queued / unavailable | Required copy and recovery |
| --- | --- | --- |
| Downloaded approved lesson/media/pack | Available only when manifest/trust/version and required resources pass validation; partial media falls back to supplied text | “Saved for offline” names resource coverage/size; unavailable media says why; expired/revoked content requires reconnect/authorized refresh |
| Scene position/notes | Supported local position persists by learner partition; position is not evidence | “Your place is saved on this device” only after storage success; storage denied says keep page open/reconnect; version mismatch follows existing migration/fallback behavior |
| Existing wired assignment/homework submission | Durable pending operation where current endpoint/policy supports it; canonical acceptance online | “Saved on this device — waiting to send”; SENDING stays pending; ACKNOWLEDGED shows actual server outcome; CONFLICT opens existing review recovery, never silent overwrite |
| Existing wired lab state/observations | Approved runtime capability/fallback determines local availability; observations queue only through existing supported seam | Explain degraded/static mode and objective continuity; restore supported lab state/return scene; local score/completion is not accepted mastery |
| Assessment | Only approved offline attempt policy/wiring; timed/live/server-only checks unavailable when policy says so | Read-only cached prompt is not permission to submit; authorized pending attempts remain pending; reconnect/revalidate attempt/version before authority accepts |
| Governed Learn next action/mastery | Last cached action may be reviewed; server supplies new action/accepts evidence; no offline mastery writes | “Review your saved activity; reconnect to send answers/get your next step.” Never relabel stale action as newly decided |
| Tutor/AI, live meetings, new messages | Live service unavailable; previously authorized static help/teacher contact instructions may be viewed; no live AI request queue | “AI help needs a connection”; retain a question draft only if supported, require explicit resend after revalidation; offer approved hint/teacher path |
| Guardian/teacher/admin data | Existing permitted caches only; do not assume private school reports, grading or approval can run offline | Last successful update and scope visible; consequential actions disabled with reason; no client-created canonical grades/attendance/approval authority |
| Reconnect/auth expiry | Existing debounce/retry/outbox, idempotency and dependency handling | Show reconnecting/pending then acknowledged; AUTH_REQUIRED prompts sign-in without deleting work; retryable failure says retained; terminal failure links to recovery |
| Account switch/update/storage pressure | Existing partition/purge/update policy | Never expose previous learner work; outbox-preserving app updates; no reload while unsaved transient work would be lost; storage warning before claiming a save |

Existing service worker weak-network cached-page fallback is 6000ms, while G11 targets ≤3s for an explicitly available saved resource. Future UI should open the verified download through the existing local resource path; do not quietly alter worker trust/cache policy to achieve the target. If current architecture cannot meet a gate, record the blocked capability and owner. Queue acknowledgment is never equivalent to mastery.

## Competitive strategy review gate

Every implementation review must answer A–G below for each changed [matrix capability](COMPETITIVE_UX_BENCHMARK.md#competitive-capability-matrix), following the [authoritative framework](PRODUCT_DESIGN_V2.md#competitive-strategy-adopt--improve--reimagine--differentiate) and [migration record](PRODUCT_DESIGN_V2_MIGRATION.md#competitive-disposition-required-for-every-implementation-pr). These are mandatory evidence fields, not optional marketing questions.

| Field | Review question | Release-blocking evidence requirement |
| --- | --- | --- |
| A Benchmark | Which competitor capability/pattern was used? | Matrix ID, primary source/configuration and evidence limits; if no equivalent was verified, say so. Never treat “not observed” as “does not exist” |
| B Disposition | Which of ADOPT / IMPROVE / REIMAGINE / DIFFERENTIATE applies? | Match the matrix, or amend its rationale before implementation approval; composite screens list separate capability decisions |
| C Preservation | Did we preserve the proven useful aspects? | Demonstrate familiar semantics and required capability parity: grades, dates, recipients, threads, review settings, release controls and deep links as applicable |
| D Friction | What friction did we remove? | Named task, LL baseline and new result; meet all applicable G01–G16 and capability-specific matrix thresholds. A screenshot cannot prove fewer actions or faster understanding |
| E Reimagination | Did the new workflow objectively improve the task, or merely look different? | Correct-task success and time/actions compared with LL before-state; required task success at least 90%, no lost necessary function, no task-time/action regression and a measured gain in at least one stated task outcome (time, actions, accuracy or comprehension). Claim improvement only when measured; superiority additionally requires the matched competitor protocol above |
| F Differentiation | Is it backed by real LiberiaLearn architecture or marketing language? | Link existing authorized seam and show end-to-end behavior on the exact build; limitations stated. Prototype position/observations, a fixture, an AI badge or a layout alone cannot establish production capability; no authority changes to fabricate a differentiator |
| G Measurement | What measurement proves the result? | Exact head/build, cohort/device/network, task fixture, baseline/result, trace/test and reviewer decision. NOT MEASURED does not pass an affected capability gate |

All affected capabilities must pass their matrix-specific acceptance gates in addition to the numbered journey gates. ADOPT requires preservation proof even without novelty. IMPROVE requires measured removal of the stated friction before it is described as improved. REIMAGINE requires task benefit, not aesthetic difference. DIFFERENTIATE requires working architecture and meaningful user behavior, not an exclusive-market claim. If no changed-task baseline is obtainable, record the measurement gap and block the affected competitive-strategy sign-off rather than relabeling the work to evade it. Existing absolute release gates still apply; passing them alone does not authorize competitive superiority claims.

For focused grading (T04), use the same submissions, rubric and feedback requirements in the current and proposed LL flow; at least 90% correct unassisted review, median task time no slower than the current LL baseline, and full required grading parity. For dates/communications/records, verify familiar semantics and correct scope, not only navigation speed. For L01–L05, verify identity, fail-closed/unknown states, authorization and continuity using the existing contracts. Native scene/evidence integration remains release-blocked until the owner's seam is available.

A PR may mark an unrelated gate out of scope with a reason; the full role rollout must pass all applicable gates. Product Design V2 is complete only when student, teacher, guardian and school scopes pass, dependencies are released, legacy contextual access is preserved and no authority/privacy regression remains. Polished anchors alone do not pass.
