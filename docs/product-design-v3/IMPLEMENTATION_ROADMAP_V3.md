## Browser acceptance contract

These are future acceptance criteria, **not tests passed in this audit**. Use authorized local/synthetic fixtures, normal middleware and real application components. Component harness evidence and authenticated Next route evidence are separate outputs. Test outcomes must name exact commit, fixture/data source, flags, role, scope, viewport, steps and assertions. No production mutation is necessary to verify presentation contracts.

Every test captures accepted screenshot plus DOM/behavior evidence. Screenshot alone does not prove accessibility or working backend. Do not infer every legacy/native route works from a navigation-only mock. Avoid asserting text that mirrors implementation while ignoring user outcomes.

Inherited measurable V2 gates include one primary activation from Today to the correct ready task; due assignment ≤2 actions; student 5/teacher ≤6/guardian ≤4/school ≤6 primary destinations; one dominant CTA, ≤2 supporting choices for young learners/≤3 for middle; ≤1 blocking plus ≤1 nonblocking visible alert. Initial viewport panel budgets are ≤3 young phone/≤4 other phone/≤6 desktop. Ready task interactive cold navigation ≤5s normal (10Mbps/50ms RTT), ≤12s weak (400kbps down/100kbps up/400ms RTT), verified saved task ≤3s offline; server acknowledgment visible ≤10s after receipt. Uncached offline is tested for honest recovery rather than impossible launch performance. Real phone/tablet evidence and the V2 per-cohort comprehension protocol are required for release certification; simulated widths cannot substitute for them, and no study or performance result is claimed here.
