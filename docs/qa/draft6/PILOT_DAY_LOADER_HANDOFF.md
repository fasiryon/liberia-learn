# Read-only scheduled Learning Preview links

Server interface: `resolvePilotDay(db, user, date, now?, env?)` in `lib/curriculum/v4/pilotDay.ts`. The database is an injected Prisma client exposing only the existing user, policy, audit and timetable delegates. Production callers use the default server environment; `env` and `now` are deterministic test seams, never request data. Date uses Liberia local time, UTC.

Return `null` conceals a disabled or unauthorized day. Otherwise return `{ date, status: "PILOT_ONLY", canonicalRecordWrites: false, periods }`. Each period includes its real timetable ID, class ID, subject, period label and bell times. An `ADMITTED` period includes the exact selection, package hash and preview URL. A `GAP` period has `UNBOUND`, `AMBIGUOUS_BINDING` or `NOT_ADMITTED`. A package-integrity or database exception propagates to the route boundary. Callers must fail closed; they must not fill gaps by searching for a similar subject or another version.

The resolver checks the server flag first, then the current student role, active school, undeleted student, explicit user allowlist, verified same-school class membership and finite pilot window. It reads existing `Timetable` records, scoped by both school and class tenant. More than 256 returned periods fails closed. It never reads assignments or historical learning data and performs no writes.

Only explicit `lessons[].timetable` bindings can produce links. Subject checks consistency with that ID binding; it is not a lookup key. Each linked lesson goes through the existing `loadStudentLearningPreview`, which re-reads current policy, membership and operator approval/audit and verifies the complete package and Civics map binding. An optional expected-timetable argument now requires that exact class membership and exact authorized timetable binding inside that same admission check. Admission through another allowed class is insufficient. The preview route checks access again when followed. No grant is cached or persisted by the resolver.

CoS resolved days and period matrix remain the sole curriculum planning authority. This function does not create a day plan or certify academic coverage. T1 owns the day-shell integration. Schoolday candidates remain gaps until their exact reviewed versions are added explicitly to the closed loader registry. The six draft.6 candidates remain unchanged and individually governed. No synthetic approval records are created here.
